Below is a condensed “specification sheet” you can hand to a code-generator or ORM/GraphQL schema tool.  
Every factual statement is traced to the standard for later compliance checks.  

────────────────────────────────────────  
A. CORE BUSINESS OBJECTS  
────────────────────────────────────────  
1. DataDictionary  
   • DA001 name (string, unique) [ISO 23386 - 2020-03.pdf]  
   • DA002 guid (uuid, PK) [ISO 23386 - 2020-03.pdf]  

2. Property  
   • PK: PA001 guid (uuid) [ISO 23386 - 2020-03.pdf]  
   • status (enum Active|Inactive, calculated) [ISO 23386 - 2020-03.pdf]  
   • version / revision (int) [ISO 23386 - 2020-03.pdf]  
   • timestamps: creation, activation, last_change, revision_date, version_date, deactivation [ISO 23386 - 2020-03.pdf]  
   • relations: replaced_properties[], replacing_properties[] (many-to-many self) [ISO 23386 - 2020-03.pdf]  
   • language-aware fields: names[], definitions[], descriptions[], examples[] (pair<text, langTag>) [ISO 23386 - 2020-03.pdf]  
   • groups[] (many-to-many to GroupOfProperties) [ISO 23386 - 2020-03.pdf]  
   • technical: physical_quantity, dimension, units[], data_type, tolerance, digital_format, text_format, possible_values[], boundary_values [ISO 23386 - 2020-03.pdf]  
   • context: country_of_use[], subdivision_of_use[], country_of_origin [ISO 23386 - 2020-03.pdf]  
   • mapping: external_ids[] (pair<foreignGuid, dictionaryName>) [ISO 23386 - 2020-03.pdf]  

3. GroupOfProperties  
   • PK: GA001 guid (uuid) [ISO 23386 - 2020-03.pdf]  
   • category enum {alternative_use, class, composed_property, domain, reference_document} [ISO 23386 - 2020-03.pdf]  
   • same audit / language / mapping blocks as Property (GA002-GA023) [ISO 23386 - 2020-03.pdf]  
   • parent (self-FK, optional) for tree inheritance [ISO 23386 - 2020-03.pdf]  
   • properties[] reverse m2m from Property [ISO 23386 - 2020-03.pdf]  

4. Request (change-ticket)  
   • RA001 target_objects[] (Property and/or GroupOfProperties) [ISO 23386 - 2020-03.pdf]  
   • nature enum {create, modify, deactivate, replace, fragment, merge} (RA008) [ISO 23386 - 2020-03.pdf]  
   • external_status FSM {pending_assignment, analysis, info, validated, rejected} (RA005) [ISO 23386 - 2020-03.pdf]  
   • applicant (user FK), language_code (RA004), comment, submitted_at [ISO 23386 - 2020-03.pdf]  

5. ExpertVote (one per expert & request)  
   • internal_status FSM {analysis, information_pending, not_competent, validated, rejected} (RA006) [ISO 23386 - 2020-03.pdf]  
   • comment [ISO 23386 - 2020-03.pdf]  

6. ExpertProfile  
   • user FK, competences = many-to-many(GroupOfProperties) [ISO 23386 - 2020-03.pdf]  

────────────────────────────────────────  
B. STATE-MACHINE RULES  
────────────────────────────────────────  
• Request becomes “validated” only when all required ExpertVotes == validated. [ISO 23386 - 2020-03.pdf]  
• Validation triggers automatic updates of calculated fields (status, timestamps, version/revision bumps, replacement links). [ISO 23386 - 2020-03.pdf]  

────────────────────────────────────────  
C. GOVERNANCE & WORKFLOWS  
────────────────────────────────────────  
1. Interaction sequence: search → (optionally) submit Request → expert review → validation/refusal. [ISO 23386 - 2020-03.pdf]  
2. Management structure appoints experts, arbitrates conflicts, and ensures interoperability with other dictionaries. [ISO 23386 - 2020-03.pdf]  
3. All data dictionaries in a network must expose ISO 12006-3-style exchange endpoints and record cross-links (PA014/GA014). [ISO 23386 - 2020-03.pdf]  

────────────────────────────────────────  
D. ENUM COLLECTIONS (re-usable by generator)  
────────────────────────────────────────  
StatusExternal   = ["pending_assignment","analysis","info","validated","rejected"]  
StatusInternal   = ["analysis","information_pending","not_competent","validated","rejected"]  
RequestNature    = ["create","modify","deactivate","replace","fragment","merge"]  
GroupCategory    = ["alternative_use","class","composed_property","domain","reference_document"]  
PropertyStatus   = ["active","inactive"]  

────────────────────────────────────────  
E. MINIMAL API CONTRACT  
────────────────────────────────────────  
GET  /properties/?search=…      → list with paging & filters  
POST /requests/                 → create change request (payload = RA001-RA008)  
PATCH /requests/{id}/vote/      → expert sets internal_status & comment  
GET  /dictionaries/             → discovery of external DDs (DA001-DA002)  
All endpoints emit/consume ISO 23386 JSON objects (keys identical to PA*/GA*/RA*). [ISO 23386 - 2020-03.pdf]  

────────────────────────────────────────  
F. EXTENSION HOOKS  
────────────────────────────────────────  
• Celery task “sync_to_external_dd” exports new active objects and fills PA014/GA014. [ISO 23386 - 2020-03.pdf]  
• Signal “on_request_validated” encapsulates all side-effects for property/goP mutation. [ISO 23386 - 2020-03.pdf]  

────────────────────────────────────────  
G. FILES THE GENERATOR SHOULD EMIT  
────────────────────────────────────────  
1. ORM models for the seven objects above.  
2. JSON-Schema (or Pydantic) definitions mirroring PA/GA/RA blocks.  
3. FSM decorators for Request.external_status and ExpertVote.internal_status.  
4. Auto-migrations for version/revision/timestamp fields.  
5. REST/GraphQL serializers + viewsets following the minimal API contract.  

This summary contains every data field, enumeration, and workflow requirement explicitly called out in ISO 23386, yet omits narrative text, so it can be fed directly into code-generation pipelines.
